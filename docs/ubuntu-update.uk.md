# Оновлення встановленого Shixpeer Ward

Команди з Mac виконуються з кореня проєкту. Використовуйте ті самі SSH-хости,
порти й HTTPS-адресу, що й під час першого встановлення. Оновлювати системні пакети,
перезавантажувати Ubuntu, видаляти базу або змінювати ключі для цього не потрібно.
Англійською: [ubuntu-update.md](ubuntu-update.md).

1. Зберіть архів:

   ```bash
   make ubuntu-bundle
   ```

2. Коли поточний імпорт Beacon закінчено, оновіть його з Mac:

   ```bash
   bash packaging/shixpeer-ward-deploy-beacon.sh BEACON_SSH_HOST https://BEACON_HOST:8443
   ```

   Для нестандартного SSH-порту використовуйте `BEACON_SSH_HOST:PORT`.
   Повторне встановлення використовує наявні облікові записи, налаштування, CA, ключ
   підпису і базу. HTTPS-служба Ward перезапуститься. Встановлювач публікує
   підписані бінарники і запускає фоновий імпорт; попередня публікація
   лишається доступною, доки вона дійсна. Через зміну нормалізації
   правила буде перезібрано; незмінені архіви можна взяти з кешу.

3. Повторіть команду встановлення агента для кожного сервера:

   ```bash
   bash packaging/shixpeer-ward-deploy-agent.sh BEACON_SSH_HOST AGENT_SSH_HOST https://BEACON_HOST:8443
   ```

   Обидва SSH-порти опційні й незалежні. Команда зберігає базу і checkpoint
   за того самого користувача і замінює перевірений бінарник. Служба агента
   перезапускається, робить update і новий scan. Наявна дійсна база зберігається. Новий Beacon відповідає
   304 на перевірку незміненого маніфесту; старий лишається сумісним,
   але повертає маніфест цілком.

4. Перевірте на сервері агента під root:

   ```bash
   /home/shixpeer-ward-agent/.shixpeer.ward/bin/shixpeer-ward-agent version
   tail -F /home/shixpeer-ward-agent/.shixpeer.ward/logs/agent.log
   ```

   Очікується версія `0.4.8-dev`. Після `scan: complete` відкрийте
   `/home/shixpeer-ward-agent/.shixpeer.ward/agent/report.md`.
   Якщо задано іншого користувача служби, використовуйте його HOME.

## Паралельне завантаження на Beacon

Для цієї зміни достатньо виконати кроки 1 і 2. Типово Beacon
готує до трьох джерел одночасно і тримає щонайбільше три HTTP-завантаження,
включно із завантаженнями окремих років NVD. Нормалізація йде по одному джерелу.
Ліміт від 1 до 8 задається прапорцем `-source-workers`. Для встановленої служби
його можна змінити через `systemctl edit shixpeer-ward-beacon-sync.service`:

```ini
[Service]
Environment=SHIXPEER_WARD_SOURCE_WORKERS=2
```

Налаштування застосовується під час наступного запуску імпорту.

## Як читати новий звіт

- `omitted_findings` — скільки деталей пропущено через ліміт виводу. Підсумкові
  лічильники враховують їх. Це не помилка сканування. Дивіться окремо на
  кількість завершених і незавершених компонентів.
- Ubuntu OSV без застосовної межі виправлення може означати як відому
  вразливість, так і статус «потрібна оцінка». Такі записи потребують перевірки,
  а не команди оновлення. Див. [формат Ubuntu OSV](https://documentation.ubuntu.com/security/security-updates/osv/).
- Для reboot звіт показує завантажену і встановлену версії ядра та
  пакети з маркера Ubuntu, якщо вони доступні. Сам маркер не доводить, що
  потрібне саме оновлення ядра.
- Порти показують локальні прив'язки. Щоб перевірити власників і Docker,
  адміністратор може окремо виконати під root:

  ```bash
  ss -lntup
  docker --host unix:///var/run/docker.sock ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
  ```

  Не додавайте демона Ward у групу docker заради звіту. Зовнішню доступність
  перевіряйте з дозволеної зовнішньої точки з урахуванням фаєрвола і NAT.


## Оновити лише дані, без встановлення нової версії

Beacon оновлює джерела за таймером, агент сам завантажує змінені частини.
Якщо потрібно оновити вручну, на Beacon під root:

```bash
systemctl start shixpeer-ward-beacon-sync.service
```

Після успішної публікації на сервері агента під root:

```bash
runuser -u shixpeer-ward-agent -- env HOME=/home/shixpeer-ward-agent /home/shixpeer-ward-agent/.shixpeer.ward/bin/shixpeer-ward-agent update
runuser -u shixpeer-ward-agent -- env HOME=/home/shixpeer-ward-agent /home/shixpeer-ward-agent/.shixpeer.ward/bin/shixpeer-ward-agent scan
```

Команда update оновлює лише базу. Щоб оновити сам Ward, використайте
перші три кроки. Жодна з цих команд не встановлює виправлення ОС.

## Автоматичний знімок Docker

Після оновлення агента встановлювач підключає окремий збирач systemd.
Він знімає локальні метадані Docker перед стартом агента і кожні
п'ять хвилин. Служба агента читає знімок зі своєї папки стану.
Стан збирача можна подивитися через
`journalctl -u shixpeer-ward-agent-capture.service`.

### Вердикти фаєрвола і Ubuntu VEX

Під час оновлення Beacon зі стандартним Canonical OSV встановлювач вмикає
супутній Ubuntu VEX. Явно заданий або вимкнений VEX зберігається.
Агент уточнює неоднозначні записи OSV за точним збігом вихідного
пакета, версії і кодового імені релізу. За відсутності збігу або
конфлікту запис лишається в review. Дані про встановлені пакети
лишаються локально.

Той самий таймер автоматично збирає dpkg-базу контейнерів Debian/Ubuntu,
слухачів і правила фаєрвола. Розділ **Local ingress firewall** показує
вердикти для нових вхідних мережевих пакетів на адресах інтерфейсів із маршрутом
типово. Для Docker DNAT показано вихідний і перетворений порт
і шлях FORWARD. Підтримуються iptables/UFW і прості фільтри INPUT/FORWARD
nftables. Непідтримувані умови або відсутність даних дають
UNKNOWN. Зовнішня доступність залежить також від зовнішньої мережі і зворотного
шляху. Збирач читає стан без зміни правил.

Для вердиктів Ubuntu використовує вже встановлені nftables, iptables і
iproute2. Якщо потрібної утиліти немає, звіт вказує прогалину покриття.

У версії 0.4.7-dev звіт також показує review окремо для завантаженого
ядра, пакетів і застосунків хоста та контейнерів. Пакетний OVAL застосовується
до Ubuntu 22.04: агент звіряє встановлений бінарний пакет і його dpkg-версію
з підтримуваним правилом Canonical. Для вже підтверджених знахідок без
версії виправлення агент шукає пов'язаний USN для того самого CVE, релізу і
вихідного пакета. У Markdown і JSON у такої версії вказано номер USN.
Для цих можливостей оновіть Beacon і агент.
