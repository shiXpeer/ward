# Обновление установленного Shixpeer Ward

English: [ubuntu-update.md](ubuntu-update.md).

Команды с Mac выполняются из корня проекта. Используйте те же SSH-хосты,
порты и HTTPS-адрес, что при первой установке. Обновлять системные пакеты,
перезагружать Ubuntu, удалять базу или менять ключи для этого не нужно.

1. Соберите архив:

   ```bash
   make ubuntu-bundle
   ```

2. Когда текущий импорт Beacon закончен, обновите его с Mac:

   ```bash
   bash packaging/shixpeer-ward-deploy-beacon.sh BEACON_SSH_HOST https://BEACON_HOST:8443
   ```

   Для нестандартного SSH-порта используйте `BEACON_SSH_HOST:PORT`.
   Повторная установка использует существующие аккаунты, настройки, CA, ключ
   подписи и базу. HTTPS-служба Ward перезапустится. Установщик публикует
   подписанные бинарники и запускает фоновый импорт; прежняя публикация
   остаётся доступной, пока она действительна. Из-за изменения нормализации
   правила будут пересобраны; неизменившиеся архивы можно взять из кеша.

3. Повторите команду установки агента для каждого сервера:

   ```bash
   bash packaging/shixpeer-ward-deploy-agent.sh BEACON_SSH_HOST AGENT_SSH_HOST https://BEACON_HOST:8443
   ```

   Оба SSH-порта опциональны и независимы. Команда сохраняет базу и checkpoint
   при том же пользователе и заменяет проверенный бинарник. Служба агента
   перезапускается, делает update и новый scan. Существующая действительная база сохраняется. Новый Beacon отвечает
   304 на проверку неизменившегося манифеста; старый остаётся совместимым,
   но возвращает манифест целиком.

4. Проверьте на сервере агента под root:

   ```bash
   /home/shixpeer-ward-agent/.shixpeer.ward/bin/shixpeer-ward-agent version
   tail -F /home/shixpeer-ward-agent/.shixpeer.ward/logs/agent.log
   ```

   Ожидается версия `0.4.8-dev`. После `scan: complete` откройте
   `/home/shixpeer-ward-agent/.shixpeer.ward/agent/report.md`.
   Если задан другой пользователь службы, используйте его HOME.

## Параллельная загрузка на Beacon

Для этого изменения достаточно выполнить шаги 1 и 2. По умолчанию Beacon
готовит до трёх источников одновременно и держит максимум три HTTP-загрузки,
включая загрузки отдельных лет NVD. Нормализация идёт по одному источнику.
Лимит от 1 до 8 задаётся флагом `-source-workers`. Для установленной службы
его можно изменить через `systemctl edit shixpeer-ward-beacon-sync.service`:

```ini
[Service]
Environment=SHIXPEER_WARD_SOURCE_WORKERS=2
```

Настройка применяется при следующем запуске импорта.

## Как читать новый отчёт

- `omitted_findings` — сколько деталей опущено из-за лимита вывода. Итоговые
  счётчики учитывают их. Это не ошибка сканирования. Смотрите отдельно на
  число завершённых и незавершённых компонентов.
- Ubuntu OSV без применимой границы исправления может означать как известную
  уязвимость, так и статус «нужна оценка». Такие записи требуют проверки,
  а не команды обновления. См. [формат Ubuntu OSV](https://documentation.ubuntu.com/security/security-updates/osv/).
- Для reboot отчёт показывает загруженную и установленную версии ядра и
  пакеты из маркера Ubuntu, если они доступны. Сам маркер не доказывает, что
  требуется именно обновление ядра.
- Порты показывают локальные привязки. Для проверки владельцев и Docker
  администратор может отдельно выполнить под root:

  ```bash
  ss -lntup
  docker --host unix:///var/run/docker.sock ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
  ```

  Не добавляйте демона Ward в группу docker ради отчёта. Внешнюю доступность
  проверяйте с разрешённой внешней точки с учётом firewall/NAT.


## Обновить только данные, без установки новой версии

Beacon обновляет источники по таймеру, агент сам скачивает изменившиеся части.
Если нужно обновить вручную, на Beacon под root:

```bash
systemctl start shixpeer-ward-beacon-sync.service
```

После успешной публикации на сервере агента под root:

```bash
runuser -u shixpeer-ward-agent -- env HOME=/home/shixpeer-ward-agent /home/shixpeer-ward-agent/.shixpeer.ward/bin/shixpeer-ward-agent update
runuser -u shixpeer-ward-agent -- env HOME=/home/shixpeer-ward-agent /home/shixpeer-ward-agent/.shixpeer.ward/bin/shixpeer-ward-agent scan
```

Команда update обновляет только базу. Для обновления самого Ward используй
первые три шага. Ни одна из этих команд не устанавливает исправления ОС.

## Автоматический снимок Docker

После обновления агента установщик подключает отдельный systemd-сборщик.
Он снимает локальные метаданные Docker перед стартом агента и каждые
пять минут. Служба агента читает снимок из своей папки состояния.
Состояние сборщика можно посмотреть через
`journalctl -u shixpeer-ward-agent-capture.service`.

### Вердикты фаервола и Ubuntu VEX

При обновлении Beacon со стандартным Canonical OSV установщик включает
сопутствующий Ubuntu VEX. Явно заданный или отключённый VEX сохраняется.
Агент уточняет неоднозначные записи OSV по точному совпадению исходного
пакета, версии и кодового имени релиза. При отсутствии совпадения или
конфликте запись остаётся в review. Данные об установленных пакетах
остаются локально.

Тот же таймер автоматически собирает dpkg-базу Debian/Ubuntu-контейнеров,
слушатели и правила фаервола. Раздел **Local ingress firewall** показывает
вердикты для новых входящих пакетов на адресах интерфейсов с маршрутом
по умолчанию. Для Docker DNAT показаны исходный и преобразованный порт
и путь FORWARD. Поддерживаются iptables/UFW и простые INPUT/FORWARD
фильтры nftables. Неподдерживаемые условия или отсутствие данных дают
UNKNOWN. Внешняя доступность зависит также от внешней сети и обратного
пути. Сборщик читает состояние без изменения правил.

Для вердиктов Ubuntu использует уже установленные nftables, iptables и
iproute2. Если нужная утилита отсутствует, отчёт указывает пробел покрытия.

В версии 0.4.7-dev отчёт также показывает review отдельно для загруженного
ядра, пакетов и приложений хоста и контейнеров. Пакетный OVAL применяется
к Ubuntu 22.04: агент сверяет установленный бинарный пакет и его dpkg-версию
с поддерживаемым правилом Canonical. Для уже подтверждённых находок без
версии исправления агент ищет связанный USN для того же CVE, релиза и
исходного пакета. В Markdown и JSON у такой версии указан номер USN.
Для этих возможностей обновите Beacon и агент.
