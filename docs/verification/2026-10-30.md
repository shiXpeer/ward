# Verification: 2026-10-30

Platform: macOS arm64. Release build: 0.3.0-dev, CGO disabled, Go 1.26.10.
No remote server was accessed or modified. Live operations fetched public advisory
sources; inventory collection/upload was not part of these runs.

## Automated checks

- gofmt, go vet and race-enabled Go tests passed; 55 test functions cover current code.
- govulncheck v1.9.0 with Go 1.26.10: `No vulnerabilities found.`
- Native macOS arm64 binaries and static Linux amd64 cross-builds succeeded.
- Shipped configurations load offline, with unique enabled IDs and supported adapters.
- JSON configurations/schemas parse; documentation links resolve locally.

Tests cover Canonical XZ checksum/cancellation/expansion bounds; record-kind selection;
OSV upstream aliases and optional package identity; Debian epoch/backport and
not-affected status; SOFA branch context; EPSS dates/invalid scores; NVD CPE/rejected
records and all-or-nothing annual import; CVE repository metadata skipping; Apple
same-host discovery and script exclusion; packed evidence integrity; state arrays;
shard integrity/expiry/rollback and incomplete-source publication refusal.

## Complete default profile: import and publication

A single run accepted all 18 enabled default sources with no source errors:
665,051 normalized records. The saved JSON was 11,984.4 MiB. Signed export succeeded
with 756 ordered shards plus the root artifact. Status confirmed all 18 sources.
The current CVE List count in that later run was 417,077; earlier individual counts
above differ because upstream data changed during validation.

This verifies full-default import, merging, storage and signed publication. Native
agent delivery was validated separately in the following runs; the complete-default
snapshot is not claimed as a completed native agent download in this report.

## Native CLI delivery on the final patched toolchain

The final 0.3.0-dev binaries, built with Go 1.26.10, completed a real quickstart run:

- all five sources fetched, normalized, signed and served by the actual Beacon CLI;
- actual agent CLI accepted 398,867 records and nine news items over local HTTPS;
- CA verification and the pinned Ed25519 key were enabled, with no verification bypass;
- saved agent feed mode was 0600;
- temporary server, state and test keys were removed after completion.

The readiness check used TCP only; the agent performed the actual authenticated
TLS and signed-content verification. A Python/OpenSSL readiness probe used in an
earlier harness failed before reaching the agent and is not counted as a delivery
success. No application TLS verification was disabled to work around that probe.

## Earlier large delivery and corruption check

Using complete downloaded Canonical cve/lsn, Debian Tracker, SOFA, EPSS and the NVD
2026 annual file, an earlier run before the toolchain refresh verified:

- 400,958 normalized records, five sources, 222 news items;
- 500 content-addressed signed feed shards;
- actual agent CLI downloaded over a local TLS server with an explicit CA/pinned key;
- corrupting the last shard was rejected and the verified checkpoint was unchanged;
- installed agent feed mode was 0600;
- temporary server, state and test keys were removed after completion.

The final race-enabled tests separately repeat shard corruption/checkpoint checks
and reject a manifest that expires during transfer. The all-years NVD adapter was
validated against every annual file, rather than only the 2026 delivery fixture.

## Limits of this evidence

Live source validation cannot guarantee upstream uptime or future schema stability.
Apple coverage follows its currently linked security index rather than all historical
bulletins. Missing package identity is preserved as unmapped evidence. Resource
limits are enforced, but full normalization still retains the database in memory.
No installed-package/container matcher or host-security verdict is claimed by these
checks. See [the real-data quickstart](../live-test.ru.md).
