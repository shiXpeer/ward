# Shixpeer Ward

Приватний моніторинг серверів і власна стрічка даних про вразливості.
Проєкт: [shixpeer.com](https://shixpeer.com). [English documentation](README.md).

Розробник: [shixpeer](https://shixpeer.com). Для операторів власних хостів
Linux і macOS та свого Beacon. Хмарного Ward і облікових записів Ward немає.
[Архітектура](docs/architecture.md) · [Безпека](SECURITY.md) ·
[Приватність](PRIVACY.md) · [Участь](CONTRIBUTING.md) ·
[Ліцензія PolyForm Internal Use 1.0.0](LICENSE).

Три програми на Go (версія розробки 0.4.8-dev):

- **shixpeer-ward-agent** збирає локальні відомості і завантажує спільну підписану базу.
- **shixpeer-ward-beacon** отримує дані з указаних джерел, об'єднує їх,
  зберігає походження записів і публікує компактну індексовану базу.

- **shixpeer-ward-relay** за потреби зберігає останній зашифрований звіт для кожного налаштованого ID сервера.

[Застосунок для macOS](apps/macos/README.md) (версія 0.1.0, `com.shixpeer.ward`)
сканує Mac, імпортує звіти й отримує зашифровані звіти. Під час відкриття
розділу застосунків Ward може звернутися до сторонніх джерел оновлень.
Підтримувані оновлення встановлюються за явною командою користувача,
іноді із запитом прав адміністратора.

Жодних PostgreSQL, SQLite й окремих серверів баз даних. Метадані — невеликі JSON-файли, база — індексовані файли на диску.
Цілком у пам'ять база не завантажується; агент завантажує лише змінені частини. Стан зберігається
типово в `~/.shixpeer.ward/` користувача, який запустив процес.

**Працює частковий локальний сканер.** Збирає ОС і ядро, пакети Debian/Ubuntu
і Homebrew, застосунки macOS, служби, порти, метадані Docker і глобальні
пакети npm/Python. Локально перевіряє підтримувані правила дистрибутивів,
мовних пакетів і NVD CPE для явно зіставлених продуктів. Складні умови
і випуски macOS потребують перевірки. Невідомі продукти, пакети всередині контейнерів
і проєктні lockfile лишаються явно неперевіреними. Нуль знахідок не означає, що вразливостей немає. Агент не встановлює
оновлення програм, не змінює правила фаєрвола і не виконує віддалені команди.

## Перевірка системи і звіт

Після налаштування і завантаження бази:

```sh
bin/shixpeer-ward-agent scan
```

У консолі одразу з'являться лічильники перевірених і неперевірених компонентів,
збіги за пріоритетом, сумнівні записи і попередження.
Перевірка локальна, без завантаження даних і без зміни встановлених застосунків.
Агент створює `report.json` і `report.md` у каталозі стану.
На Mac звіт можна відкрити так:

```sh
open "$HOME/.shixpeer.ward/agent/report.md"
```

`scan -report-dir .local/reports` зберігає звіти в інший каталог.
Відсутність збігів не означає безпеку: неперевірені розділи і записи,
що потребують ручної перевірки, показано окремо. Докладніше: [покриття сканера](docs/scanning.md).


## Просте оновлення бази

Один раз збережіть джерело і довірений публічний ключ видавця:

```sh
bin/shixpeer-ward-agent setup -feed-url https://YOUR-BEACON/v1/manifest.json -trusted-key /path/to/feed.pub
```

Для приватного HTTPS додайте `-ca-file /path/to/ca.crt`. Для публічного HTTPS
використовуються системні сертифікати. Приватні ключі агенту не потрібні.
Адреса вище — приклад: готового публічного сервісу Ward поки немає.

Далі достатньо однієї команди:

```sh
bin/shixpeer-ward-agent update
```

Запуск без аргументів також оновлює базу. Екосистема і список пакетів не потрібні:
усі агенти отримують спільну базу, повторно завантажуються лише змінені об'єкти.
Це оновлення даних про вразливості; встановлені застосунки воно не оновлює.

Налаштування зберігаються атомарно з правами 600 у `~/.shixpeer.ward/config/agent.json`,
база і звіти — в `~/.shixpeer.ward/agent/` на Linux і macOS, включно з root
(`/root/.shixpeer.ward/`). Використовуйте одного користувача для setup, update і scan.
`-config` і `-state` лишаються явними перевизначеннями.
Публічний ключ копіюється в налаштування; CA за стандартного setup копіюється в домашній config.
Явні прапорці перевизначають налаштування лише для поточного запуску; щоб зберегти
зміни, використовуйте setup. Змінна `SHIXPEER_WARD_AGENT_FEED_URL` має
пріоритет над збереженим URL, явний `-feed-url` — над змінною.

Підпис, строк дії і захист від відкату обов'язкові. Ключ — необов'язковий
аргумент після початкового налаштування довіри. Для локального lookup
екосистему задають явно. Для автоматичного збору і перевірки використовуйте scan.

## Швидкий локальний тест

Потрібен Go 1.26.10+. Команди виконуються з кореня проєкту:

```sh
make build
mkdir -p "$HOME/.shixpeer.ward/demo"
bin/shixpeer-ward-beacon init -pki "$HOME/.shixpeer.ward/demo/pki"
bin/shixpeer-ward-beacon sync -sources configs/beacon.demo.json -state "$HOME/.shixpeer.ward/demo/beacon"
bin/shixpeer-ward-beacon export -state "$HOME/.shixpeer.ward/demo/beacon" -out "$HOME/.shixpeer.ward/demo/public" -signing-key "$HOME/.shixpeer.ward/demo/pki/signing.key"
bin/shixpeer-ward-beacon serve -state "$HOME/.shixpeer.ward/demo/beacon" -out "$HOME/.shixpeer.ward/demo/public" -tls-cert "$HOME/.shixpeer.ward/demo/pki/server.crt" -tls-key "$HOME/.shixpeer.ward/demo/pki/server.key"
```

В іншому терміналі:

```sh
bin/shixpeer-ward-agent collect -state "$HOME/.shixpeer.ward/demo/agent"
bin/shixpeer-ward-agent pull -state "$HOME/.shixpeer.ward/demo/download" -feed-url https://localhost:8443/v1/manifest.json -ca-file "$HOME/.shixpeer.ward/demo/pki/ca.crt" -trusted-key "$HOME/.shixpeer.ward/demo/pki/feed.pub"
bin/shixpeer-ward-agent lookup -state "$HOME/.shixpeer.ward/demo/download" -ecosystem npm -package ward-demo-package
```

Демо використовує синтетичний запис і не звертається до зовнішніх джерел.
Знімок комп'ютера лишається в `~/.shixpeer.ward/demo/agent/snapshot.json`. Підписана база
зберігається в `~/.shixpeer.ward/demo/download/database/`. Ніхто не отримує ваш список пакетів.

## Як влаштована довіра

HTTPS підтверджує сервер за допомогою його приватного TLS-ключа. Знімки бази окремо
підписуються ключем Ed25519 — цей підпис працює і за доставки через GitHub.
Агенту передаються лише `ca.crt` і `feed.pub`, через заздалегідь довірений канал.
`server.key`, `signing.key` і `ca.key` не можна комітити, публікувати або віддавати агентам.
Підпис підтверджує видавця і незмінність даних, а не правильність кожного advisory.

Агент завантажує спільний знімок і не питає про конкретні пакети чи CVE. Дзеркало все
одно бачить IP і час завантаження — повної анонімності це не дає. Ізоляція процесів
і мінімальні права налаштовуються на рівні ОС; окремі goroutine її не замінюють.

### Джерела за замовчуванням

Профілі, що постачаються: `configs/beacon.default.json` і розширений
`configs/beacon.extended.json`. Повний довідник із явним статусом інтеграцій:
`configs/source-catalog.json`. Покриття Ubuntu/Debian/macOS, посилання на першоджерела
й обмеження описані в [огляді джерел](docs/source-catalog.uk.md).
Каталог не означає, що всі перелічені адаптери вже реалізовані.

## Нова компактна база (0.4)

Підписаний протокол v3 і дисковий формат 3 замінюють старий JSON feed. Потрібні
обидва нові бінарники й окремі каталоги стану. Повний імпорт джерел
виконується на Beacon. Агент зберігає компактні частини на диску і шукає записи
бінарним пошуком за індексом; пакети і версії в мережу не надсилаються.

`-profile all` публікує всі підтримувані дані. Явний спільний профіль
`-profile prototype` залишає правила Ubuntu 24.04 LTS, Debian 12/bookworm і macOS.
Профіль не обирається автоматично за складом сервера. `lookup` — перегляд
записів, а не готовий аналіз вразливостей встановленого програмного забезпечення. `beacon news` потоково видає до 200 останніх критичних записів і записів KEV. Відомості
KEV/EPSS доступні через `lookup -group r -id CVE-...`.
