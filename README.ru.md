# Shixpeer Ward

Приватный мониторинг серверов и собственная лента данных об уязвимостях.
Проект: [shixpeer.com](https://shixpeer.com). [English documentation](README.md).

Два приложения на Go:

- **shixpeer-ward-agent** собирает локальные сведения и скачивает общую подписанную базу.
- **shixpeer-ward-beacon** получает данные из указанных источников, объединяет их,
  сохраняет происхождение записей и публикует компактную индексированную базу.

Никаких PostgreSQL, SQLite и отдельных серверов баз данных. Метаданные — небольшие JSON-файлы, база — индексированные файлы на диске.
Целиком в память база не загружается; агент скачивает только изменившиеся части. Состояние хранится
в системных каталогах, а не рядом с бинарником.

**Работает частичный локальный сканер.** Собирает ОС/ядро, пакеты Debian/Ubuntu
и Homebrew, приложения macOS, сервисы, порты, метаданные Docker и глобальные
npm/Python-пакеты. Локально проверяет поддерживаемые правила дистрибутивов,
языковых пакетов и NVD CPE для явно сопоставленных продуктов. Сложные условия
и релизы macOS требуют проверки. Неизвестные продукты, пакеты внутри контейнеров
и проектные lockfile остаются явно непроверенными. Автоматических изменений ПО нет.

## Ubuntu: первый тест и установка демонов

[Пошаговая инструкция](docs/ubuntu-deployment.ru.md): отдельный Beacon,
проверенная установка агента двумя командами после подготовки доверия, systemd,
отчёты и перенос старого состояния. Архив: `make ubuntu-bundle`.

## Проверка системы и отчёт

После настройки и скачивания базы:

```sh
bin/shixpeer-ward-agent scan
```

В консоли сразу появятся счётчики проверенных и непроверенных компонентов,
совпадения по приоритету, сомнительные записи и предупреждения.
Проверка локальная, без скачивания данных и изменения установленных приложений.
Агент создаёт `report.json` и `report.md` в каталоге состояния.
На Mac открыть отчёт можно так:

```sh
open "$HOME/.shixpeer.ward/agent/report.md"
```

`scan -report-dir .local/reports` сохраняет отчёты в другой каталог.
Отсутствие совпадений не означает безопасность: непроверенные разделы и записи,
требующие ручной проверки, показаны отдельно. Подробнее: [покрытие сканера](docs/scanning.md).


## Простое обновление базы

Один раз сохраните источник и доверенный публичный ключ издателя:

```sh
bin/shixpeer-ward-agent setup -feed-url https://YOUR-BEACON/v1/manifest.json -trusted-key /path/to/feed.pub
```

Для частного HTTPS добавьте `-ca-file /path/to/ca.crt`. Для публичного HTTPS
используются системные сертификаты. Приватные ключи агенту не нужны.
Адрес выше — пример: готового публичного сервиса Ward пока нет.

Дальше достаточно одной команды:

```sh
bin/shixpeer-ward-agent update
```

Запуск без аргументов также обновляет базу. Экосистема и список пакетов не нужны:
все агенты получают общую базу, повторно загружаются только изменившиеся объекты.
Это обновление данных об уязвимостях; установленные приложения оно не обновляет.

Настройки сохраняются атомарно с правами 600 в `~/.shixpeer.ward/config/agent.json`,
база и отчёты — в `~/.shixpeer.ward/agent/` на Linux и macOS, включая root
(`/root/.shixpeer.ward/`). Используйте одного пользователя для setup/update/scan.
`-config` и `-state` остаются явными переопределениями.
Публичный ключ копируется в настройки; CA при стандартном setup копируется в домашний config.
Явные флаги переопределяют настройки только для текущего запуска; для сохранения
изменений используйте setup. Переменная `SHIXPEER_WARD_AGENT_FEED_URL` имеет
приоритет над сохранённым URL, явный `-feed-url` — над переменной.

Подпись, срок действия и защита от отката обязательны. Ключ — необязательный
аргумент после первоначальной настройки доверия. Для локального lookup
экосистема задаётся явно. Для автоматического сбора и проверки используйте scan.

## Быстрый локальный тест

Нужен Go 1.26.10+. Команды выполняются из корня проекта:

```sh
make build
mkdir -p "$HOME/.shixpeer.ward/demo"
bin/shixpeer-ward-beacon init -pki "$HOME/.shixpeer.ward/demo/pki"
bin/shixpeer-ward-beacon sync -sources configs/beacon.demo.json -state "$HOME/.shixpeer.ward/demo/beacon"
bin/shixpeer-ward-beacon export -state "$HOME/.shixpeer.ward/demo/beacon" -out "$HOME/.shixpeer.ward/demo/public" -signing-key "$HOME/.shixpeer.ward/demo/pki/signing.key"
bin/shixpeer-ward-beacon serve -state "$HOME/.shixpeer.ward/demo/beacon" -out "$HOME/.shixpeer.ward/demo/public" -tls-cert "$HOME/.shixpeer.ward/demo/pki/server.crt" -tls-key "$HOME/.shixpeer.ward/demo/pki/server.key"
```

В другом терминале:

```sh
bin/shixpeer-ward-agent collect -state "$HOME/.shixpeer.ward/demo/agent"
bin/shixpeer-ward-agent pull -state "$HOME/.shixpeer.ward/demo/download" -feed-url https://localhost:8443/v1/manifest.json -ca-file "$HOME/.shixpeer.ward/demo/pki/ca.crt" -trusted-key "$HOME/.shixpeer.ward/demo/pki/feed.pub"
bin/shixpeer-ward-agent lookup -state "$HOME/.shixpeer.ward/demo/download" -ecosystem npm -package ward-demo-package
```

Демо использует синтетическую запись и не обращается к внешним источникам.
Снимок компьютера остаётся в `~/.shixpeer.ward/demo/agent/snapshot.json`. Подписанная база
сохраняется в `~/.shixpeer.ward/demo/download/database/`. Никто не получает ваш список пакетов.

## Как устроено доверие

HTTPS подтверждает сервер с помощью его приватного TLS-ключа. Снимки базы отдельно
подписываются ключом Ed25519 — эта подпись работает и при доставке через GitHub.
Агенту передаются только `ca.crt` и `feed.pub`, через заранее доверенный канал.
`server.key`, `signing.key` и `ca.key` нельзя коммитить, публиковать или отдавать агентам.
Подпись подтверждает издателя и неизменность данных, а не правильность каждого advisory.

Агент скачивает общий снимок, не спрашивает про конкретные пакеты/CVE. Зеркало всё
равно видит IP и время загрузки — полной анонимности это не даёт. Изоляция процессов
и минимальные права настраиваются на уровне ОС; отдельные goroutine её не заменяют.

## Новая компактная база (0.4)

Подписанный протокол v3 и дисковый формат 3 заменяют старый JSON feed. Нужны
оба новых бинарника и отдельные каталоги состояния. Полный импорт источников
выполняется на Beacon. Агент хранит компактные части на диске и ищет записи
бинарным поиском по индексу; пакеты и версии в сеть не отправляются.

`-profile all` публикует все поддерживаемые данные. Явный общий профиль
`-profile prototype` оставляет правила Ubuntu 24.04 LTS, Debian 12/bookworm и macOS.
Профиль не выбирается автоматически по составу сервера. `lookup` — просмотр
записей, а не готовый анализ уязвимостей установленного ПО. `beacon news` потоково выдаёт до 200 последних критических/KEV записей. Сведения
KEV/EPSS доступны через `lookup -group r -id CVE-...`.

[Замеры и проверки](docs/verification/compact-0.4.md).
